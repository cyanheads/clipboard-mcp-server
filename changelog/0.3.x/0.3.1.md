# 0.3.1 — 2026-11-21

## Added

- **`clipboard_read` `files` format** ([#59](https://github.com/cyanheads/clipboard-mcp-server/issues/59)) returns the absolute paths of copied files, one per line: each item's `public.file-url` on macOS, `text/uri-list` `file:` URIs on Linux, the FileDrop list on Windows. Paths only; no file is opened. `auto` ranks `files` above `image`, `clipboard_inspect` lists it in `availableFormats`/`primaryFormat`, and a path holding a line break (on Linux, also one whose bytes are not UTF-8) is left out and counted in the `notice`.
- **`itemCount` and `item`** ([#57](https://github.com/cyanheads/clipboard-mcp-server/issues/57)): both tools report `itemCount`, and `clipboard_read` takes an optional 0-based `item` to read one macOS pasteboard item alone. Without it, a read over several items names the items it drew on in the `notice`. `representationId` encodes `item`, so a continuation with another `item` fails `representation_changed`; an `item` past the last fails `format_unavailable`. An `image` read of one item also decodes the item's own JPEG, HEIC, or GIF, which AppKit converts to TIFF only for the whole pasteboard.

## Changed

- **Server `instructions`**, tool descriptions, README, `docs/design.md`, and the `clipboard-guide` skill (1.0 → 1.1) describe `files` and `item`.
- **Linux X11 and Wayland backends** share inspection and reads through `linux-selection.ts`; `uri-list.ts` parses `text/uri-list` for `files`.
- **`ClipboardService`** assigns its backend in the constructor body instead of a parameter property (`erasableSyntaxOnly`).
- **`CLIPBOARD_READ_ONLY` description** in `manifest.json`, `server.json`, and `.env.example` says `clipboard_write` is absent from `tools/list` and uncallable, but listed as disabled in the server manifest, landing page, and startup log.
- **Framework sync** refreshes `framework-skills/`, `scripts/` (drops `audit-open-index-signatures.ts`), the changelog template, and `.env.example` (`MCP_JWT_EXPECTED_AUDIENCE`, `MCP_JWT_EXPECTED_ISSUER`); `engines.bun` is `>=1.4.4` and the `typescript-v6` dev alias is gone.

## Fixed

- **An invalid `CLIPBOARD_READ_ONLY`** ([#51](https://github.com/cyanheads/clipboard-mcp-server/issues/51)) fails startup behind the `Configuration error — server failed to start` banner, naming the accepted values, instead of an uncaught `McpError` stack.
- **macOS `rtf` reads** ([#54](https://github.com/cyanheads/clipboard-mcp-server/issues/54)) return `public.rtf` as written; with only `com.apple.flat-rtfd`, the package is converted to RTF through `NSAttributedString`. A package that does not decode fails `format_unavailable`, and `auto` moves on. Flat RTFD was previously returned as UTF-8-decoded binary.
- **The plain-text fallback of an `html` write** on macOS and Windows ([#56](https://github.com/cyanheads/clipboard-mcp-server/issues/56)) follows the HTML Standard's `innerText` rules: line breaks at `<br>` and block elements, tabs between table cells, `<pre>` whitespace kept. It previously collapsed every boundary to one space and fused `th`, `dt`, `dd`, and `hr` text. List markers and numbering are still dropped.
- **`clipboard_inspect` `content[]`** ([#58](https://github.com/cyanheads/clipboard-mcp-server/issues/58)) escapes `|` and backticks in raw type names so each reads back from a GFM parse; a name holding CR, LF, NUL, or a backslash before `|` switches the section to a fenced JSON block of `rawTypes`.
