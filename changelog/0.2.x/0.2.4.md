# 0.2.4 — 2026-09-24

The Windows changes are tested against the generated PowerShell through a modeled helper, never run on Windows; native Windows behavior is unverified.

## Added

- **`representationId` on `clipboard_read`** — every read returns an opaque token for the value and format it was cut from, and accepts the previous slice's token as input; a continuation whose token no longer matches fails `representation_changed` (`Conflict`) with no bytes. On macOS the token follows `NSPasteboard.changeCount`, so re-publishing identical content also conflicts. ([#38](https://github.com/cyanheads/clipboard-mcp-server/issues/38))

## Changed

- **`representation_changed`** also reports a clipboard change caught inside one read — the macOS `changeCount` samples differ, or the two Windows `HTML Format` calls hash differently (previously an untyped error). ([#38](https://github.com/cyanheads/clipboard-mcp-server/issues/38))
- **macOS text and HTML reads** are raw JXA `dataForType` reads, text from the first non-nil of `public.utf8-plain-text` and `public.plain-text`; `pbpaste` is no longer used. ([#42](https://github.com/cyanheads/clipboard-mcp-server/issues/42))
- **Windows image reads** return a registered `PNG` that `System.Drawing` decodes before falling back to `GetImage()`, and inspection maps `DeviceIndependentBitmap` and `Format17` (CF_DIBV5) to `image`. ([#43](https://github.com/cyanheads/clipboard-mcp-server/issues/43))
- **Windows ranged reads** encode each slice straight from the full array with `[Convert]::ToBase64String($bytes, $offset, $length)` instead of copying it through a range-operator index array. ([#47](https://github.com/cyanheads/clipboard-mcp-server/issues/47))
- **`clipboard_read` `limit` description** now says `limit` is optional in a ranged read, matching the handler.

## Fixed

- **Partial image slices** attach no `image/png` block: only a response holding the whole image does, and a partial slice carries its base64 and byte range in the text, to be base64-decoded per chunk and concatenated in offset order. ([#32](https://github.com/cyanheads/clipboard-mcp-server/issues/32))
- **`clipboard_inspect` `rawTypes`** report `bytes` only for a measured size (`0` still means present and empty); an unsized type omits it, and nil, null, or unreadable data sets `measurementFailed: true` and no longer makes its format available. ([#41](https://github.com/cyanheads/clipboard-mcp-server/issues/41))
- **Windows text reads** move on to the next text format when `GetData` returns no string for the first. ([#41](https://github.com/cyanheads/clipboard-mcp-server/issues/41))
- **macOS text and HTML reads** keep a leading byte-order mark, so `totalByteSize` matches `clipboard_inspect`; a pasteboard holding only UTF-16 plain text reads as its UTF-8 translation. ([#42](https://github.com/cyanheads/clipboard-mcp-server/issues/42))
- **Zero-byte images** on macOS and Windows read as an empty image success instead of `format_unavailable`, and a zero-length or undecodable `public.png` beside a decodable `public.tiff` returns the converted TIFF. ([#43](https://github.com/cyanheads/clipboard-mcp-server/issues/43))
- **`clipboard_read` `auto` over an unreadable type listing** fails `inspect_unreadable` (`SerializationError`) with a recovery hint instead of an untyped `InternalError`. ([#45](https://github.com/cyanheads/clipboard-mcp-server/issues/45))
- **`auto`** moves on to the next listed format when one reads as absent (an image no decoder accepts), instead of failing while text is readable. ([#46](https://github.com/cyanheads/clipboard-mcp-server/issues/46))
