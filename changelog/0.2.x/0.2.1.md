# 0.2.1 — 2026-09-09

## Added

- **`clipboard_read`** gains optional `offset`/`limit` inputs for retrieving content above the size limit in bounded slices instead of erroring outright. Output gains `totalByteSize`, `complete`, and `nextOffset` (absent once `complete`); follow `nextOffset` until `complete` is `true`. `limit` is clamped to the format's size limit and has a floor of 4 bytes so a text slice always holds a whole UTF-8 character. ([#7](https://github.com/cyanheads/clipboard-mcp-server/issues/7))

## Changed

- **`ClipboardBackend.read()`** is now always ranged: `pbpaste`/`xclip`/`wl-paste` stream through the new `collectByteWindow()` sink (`src/services/clipboard/byte-window.ts`) instead of buffering the full representation, and the macOS JXA / Windows PowerShell read scripts take `offset`/`limit` and return only the requested window. An unranged `clipboard_read` now requests `SIZE_LIMIT + 1` bytes and raises `content_too_large` from the measured total rather than buffering the whole payload first. ([#7](https://github.com/cyanheads/clipboard-mcp-server/issues/7))

## Fixed

- **Linux `clipboard_inspect`** no longer buffers a representation to measure it — both the X11 and Wayland backends measure each advertised type with the new `countBytes()`, which consumes the child's stdout and keeps a running total without retaining any chunk. ([#26](https://github.com/cyanheads/clipboard-mcp-server/issues/26))
- **macOS `pbpaste`/`pbcopy`** now spawn with `LC_ALL=en_US.UTF-8` (`UTF8_ENV`), so read/write byte counts no longer depend on the locale the server process inherited — previously a non-UTF-8 locale (e.g. a launch under `env -i`) silently mangled multi-byte text. ([#29](https://github.com/cyanheads/clipboard-mcp-server/issues/29))
