# 0.2.0 — 2026-09-08

## Added

- **`clipboard_write`** gains `clear: boolean` (default `false`) to empty the clipboard outright. Each backend uses its platform's ownership-releasing primitive — macOS JXA `clearContents`, Linux X11 `xsel --clipboard --clear` (a new dependency alongside `xclip`), Linux Wayland `wl-copy --clear`, Windows `Clipboard::Clear()` — rather than writing empty content, which would leave a zero-byte representation behind. Returns `cleared: true`, `byteSize: 0`, and `previousContent` when recoverable. ([#24](https://github.com/cyanheads/clipboard-mcp-server/issues/24))
- **`clipboard_read`**'s `image` format now carries `width`/`height` on Linux X11 and Wayland, read from the PNG `IHDR` chunk via the new `readPngDimensions()` — matching what macOS and Windows already report. ([#20](https://github.com/cyanheads/clipboard-mcp-server/issues/20))

## Changed

- **Breaking:** `clipboard_write`'s `content` is now optional, and a call supplying neither `content` nor `clear: true`, both at once, or an empty `content: ""` is rejected at the schema. Previously `content: ""` wrote a zero-byte text representation; callers that relied on that now pass `clear: true`. ([#24](https://github.com/cyanheads/clipboard-mcp-server/issues/24))
- **`clipboard_inspect`**'s `rawTypes[].bytes` is now optional: an entry whose size measurement failed carries `measurementFailed: true` and no `bytes`, instead of a misleading `bytes: 0`. A backend whose native helper returns output this server can't parse now throws a typed `inspect_unreadable` error instead of reporting an empty clipboard. X11's `xclip` reporting no owner for the CLIPBOARD selection is treated as a genuinely empty clipboard, not a failure. ([#23](https://github.com/cyanheads/clipboard-mcp-server/issues/23))
- **Linux Wayland writes** (`runWlCopy()`) now resolve on the spawned `wl-copy` process's own exit 0, rejecting with captured stderr on a non-zero exit, spawn error, or broken stdin — replacing a fixed 50ms timer that could resolve before the selection was actually set. `detectBackend()` also probes `wl-copy` alongside `wl-paste` so a session missing only the write half fails at startup with install guidance rather than a bare `ENOENT` on first write. ([#21](https://github.com/cyanheads/clipboard-mcp-server/issues/21))
