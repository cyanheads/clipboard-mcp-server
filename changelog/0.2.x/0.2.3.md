# 0.2.3 — 2026-09-24

## Changed

- **`clipboard_inspect`, `clipboard_read`, and `clipboard_write`** declare `clipboard_unavailable` (`ServiceUnavailable`) for a missing helper or an unreachable display or compositor; `data.recovery.hint` names the install command or session variable to fix. ([#36](https://github.com/cyanheads/clipboard-mcp-server/issues/36))
- **macOS writes** run one static JXA script that reads its payload from stdin; `pbcopy` is no longer used. ([#30](https://github.com/cyanheads/clipboard-mcp-server/issues/30))
- **Windows writes** send their payload on stdin to one static PowerShell script, and the HTML write's plain-text fallback goes out as `UnicodeText` instead of ANSI `Text`. ([#31](https://github.com/cyanheads/clipboard-mcp-server/issues/31), [#37](https://github.com/cyanheads/clipboard-mcp-server/issues/37))
- **`clipboard_write` description** now says Linux HTML writes have no stripped fallback: a plain-text paste can receive the HTML markup.

## Fixed

- **macOS text writes** stay `public.utf8-plain-text` when the content starts with an RTF (`{\rtf`) or EPS header, so they read back byte-identical. ([#30](https://github.com/cyanheads/clipboard-mcp-server/issues/30))
- **Writes up to 1 MiB** succeed on macOS and Windows; payloads no longer travel in process arguments, which failed macOS HTML writes above ~390 KB with `E2BIG`. Native Windows verification is pending. ([#31](https://github.com/cyanheads/clipboard-mcp-server/issues/31))
- **macOS HTML, RTF, and image reads** at an `offset` past the end return the empty complete slice, and an HTML read with no HTML present returns `format_unavailable`, instead of internal `TypeError`s. ([#33](https://github.com/cyanheads/clipboard-mcp-server/issues/33))
- **Wayland reads, sizes, and `previousContent`** no longer gain a trailing `\n`: every `wl-paste` payload read and measurement passes `--no-newline`. ([#35](https://github.com/cyanheads/clipboard-mcp-server/issues/35))
- **Linux helper outcomes** — empty clipboard, absent format, missing helper, unreachable display — map to `format_unavailable` or `clipboard_unavailable` across both xclip and wl-clipboard diagnostic generations instead of surfacing as `InternalError`. Presence comes from the type listing, so an `xclip`-owned selection no longer answers `html` or `image` with its text. ([#36](https://github.com/cyanheads/clipboard-mcp-server/issues/36))
- **Zero-byte representations** that the clipboard lists read as empty content instead of an error; a zero-byte image attaches no image block. ([#36](https://github.com/cyanheads/clipboard-mcp-server/issues/36))
- **Malformed macOS or Windows read-helper output** fails as `SerializationError`, never `format_unavailable`, and never echoes clipboard bytes. ([#36](https://github.com/cyanheads/clipboard-mcp-server/issues/36))
- **Windows HTML** is written as a UTF-8 CF_HTML envelope and read as its `[StartFragment, EndFragment)` fragment, so it round-trips `clipboard_write` exactly. Pasting into native CF_HTML consumers has not yet been verified on Windows. ([#37](https://github.com/cyanheads/clipboard-mcp-server/issues/37))
- **X11 `clipboard_write`** resolves once `xclip` owns the selection, instead of waiting until another client takes it. ([#40](https://github.com/cyanheads/clipboard-mcp-server/issues/40))

## Dependencies
